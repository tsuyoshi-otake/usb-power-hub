# KiCad project (Rev0.4, issue #6)

> **WIP — MANUFACTURING PROHIBITED.** Rev0.4 is captured, placed and routed in KiCad 9.0.8
> until the design is complete, then imported into EasyEDA (D32). Nothing here is orderable.

Everything under `source/` and `libraries/` is generated by the scripts in `scripts/` from
documents in the repository. Change the document, then re-run the generator. A board or
schematic saved from the KiCad GUI is overwritten by the next run; open the project to look,
not to edit.

| Path | Holds |
|---|---|
| `source/` | The KiCad project: `usb-power-hub.kicad_pro` (rules, net classes), the root sheet and six sub-sheets, `usb-power-hub.kicad_pcb` (stackup, outline, placed footprints). |
| `libraries/` | The project symbols and footprints and `library.json`, the datasheet facts they are checked against (its README). |
| `PLACEMENT_Rev0.4.md` | Where every part sits on the board, and why (P3). |
| `ROUTING_Rev0.4.md` | The plane, the hand-drawn tracks (USB pairs, Kelvin taps, power trunks), the zones, the router's classes, keepouts, layer preferences and costs, the patch drawn after the router, and why (P4). |
| `routing/` | The router's session `usb-power-hub.ses` and `autoroute.json`, which records the router input, the jar, the Java runtime and the arguments that produced it. |
| `scripts/` | The generators, their checkers and the checkers' negative tests. |

## Pipeline

Run with KiCad 9.0's own Python, which carries `pcbnew`, from the repository root, in this
order. Each generator runs its checker when it has written its files; exit status 0 means
written and checked.

| Step | Script | Reads | Writes | Checked by | Negative tests |
|---|---|---|---|---|---|
| 1 | `make_project.py` | `design/experiments/stackup-impedance/stackups.json` | `.kicad_pro`, a bare `.kicad_pcb` | `make_project.py --check` | `test_make_project.py` |
| 2 | `make_libraries.py` | `libraries/library.json` | `libraries/usb-power-hub.kicad_sym`, `usb-power-hub.pretty/` | `check_libraries.py` | `test_check_libraries.py` |
| 3 | `make_schematic.py` | `design/circuit/CIRCUIT_DESIGN_Rev0.4_netlist.md` (the capture list), the symbols | the seven `.kicad_sch` | ERC, `check_schematic.py` | `test_check_schematic.py` |
| 4 | `autoroute.py` | what `make_pcb.py --dsn` writes from the step-5 inputs | `routing/usb-power-hub.ses`, `routing/autoroute.json` | `make_pcb.py`, which refuses a session made from other input | — |
| 5 | `make_pcb.py` | the schematic's exported netlist, `PLACEMENT_Rev0.4.md`, `ROUTING_Rev0.4.md`, the session, the footprints | `.kicad_pcb` | `make_project.py --check`, `check_pcb.py`, `check_routing.py` (each with DRC) | `test_check_pcb.py`, `test_check_routing.py` |

```sh
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_project.py
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_libraries.py
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_schematic.py
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/autoroute.py --java <java.exe> --jar <freerouting-2.5.0.jar>
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_pcb.py
```

Step 4 needs Freerouting 2.5.0 and a Java runtime, which are not in the repository; the
script refuses any jar or runtime other than the pinned ones (their SHA-256 is in the
script). It is needed only when its input changes: `make_pcb.py` stops and asks for it when
the session no longer matches the board it would route. The committed session took 17 min
(56 passes, single-threaded) on this machine, and 23 min with other router runs beside it. A new session also needs a new patch
table (`ROUTING_Rev0.4.md`, *After the router*).

`make_project.py` writes a bare board, so `make_pcb.py` runs after it; until then
`check_pcb.py` fails, because the board holds no footprints. A re-run of any generator writes
the same bytes: UUIDs are derived, and `make_pcb.py` seeds pcbnew's UUID generator, which
decides the order footprints are saved in.

The negative tests corrupt copies of the files in a temporary directory and expect the
checker to name each fault; they never write to `source/` or `libraries/`.

## Where a change starts

| Change | Edit | Then run |
|---|---|---|
| A part, pin or net | the capture list | steps 3 to 5 |
| A part's position or rotation | `PLACEMENT_Rev0.4.md` | steps 4 and 5 |
| A hand-drawn track, a zone, a router class or keepout | `ROUTING_Rev0.4.md` | steps 4 and 5 |
| A symbol or footprint | `libraries/library.json`, `make_libraries.py` | steps 2 to 5 |
| Rules, net classes, stackup, outline | `make_project.py` | step 1, then 4 and 5 |

## What the checks cannot see

Each checker's docstring ends with a "What it CANNOT see" list (CLAUDE.md §8). In short: the
checkers compare the KiCad files with the documents, not the documents with the physics.
Whether the circuit is right is the circuit document's and its `_calc.py`'s; whether the
routing is good beyond the rules `check_routing.py` lists is a review's; heights, the plug overmold and the enclosure are V-MECH-01's.
