# KiCad project (Rev0.7, issues #6, #8, #10, #13, #14)

> **WIP — MANUFACTURING PROHIBITED.** Rev0.7 is captured, placed, routed and labelled in
> KiCad 9.0.8 until the design is complete, then imported into EasyEDA (D32). Its candidate
> manufacturing set (step 7) is a `WIP` set: nothing here is orderable.

Everything under `source/` and `libraries/` is generated by the scripts in `scripts/` from
documents in the repository. Change the document, then re-run the generator. A board or
schematic saved from the KiCad GUI is overwritten by the next run; open the project to look,
not to edit.

| Path | Holds |
|---|---|
| `source/` | The KiCad project: `usb-power-hub.kicad_pro` (rules, net classes), `usb-power-hub.kicad_dru` (JLCPCB's hole figures for vias and PTH pads as custom DRC rules, issue #8), the root sheet and six sub-sheets, `usb-power-hub.kicad_pcb` (stackup, outline, placed footprints). |
| `libraries/` | The project symbols and footprints and `library.json`, the datasheet facts they are checked against (its README). |
| `PLACEMENT_Rev0.7.md` | Where every part sits on the board, and why (P3), and its silkscreen labels: text, position, size, stroke and leader (P5). |
| `ROUTING_Rev0.7.md` | The plane, the hand-drawn tracks (USB pairs, Kelvin taps, power trunks), the zones, the router's classes, keepouts, layer preferences and costs, the patch drawn after the router, and why (P4). |
| `routing/` | `carried.json`, the tracks and vias of Rev0.5's routing that still stand on this board (written by `carry.py`); the router's session `usb-power-hub.ses` and `autoroute.json`, which records the router input, the jar, the Java runtime and the arguments that produced it. |
| `scripts/` | The generators, their checkers and the checkers' negative tests; the two independent checks of a candidate set. |

## Pipeline

Run with KiCad 9.0's own Python, which carries `pcbnew`, from the repository root, in this
order. Each generator runs its checker when it has written its files; exit status 0 means
written and checked.

| Step | Script | Reads | Writes | Checked by | Negative tests |
|---|---|---|---|---|---|
| 1 | `make_project.py` | `design/experiments/stackup-impedance/stackups.json` | `.kicad_pro`, `.kicad_dru`, a bare `.kicad_pcb` | `make_project.py --check` | `test_make_project.py` |
| 2 | `make_libraries.py` | `libraries/library.json` | `libraries/usb-power-hub.kicad_sym`, `usb-power-hub.pretty/` | `check_libraries.py` | `test_check_libraries.py` |
| 3 | `make_schematic.py` | `design/circuit/CIRCUIT_DESIGN_Rev0.7_netlist.md` (the capture list), the symbols | the seven `.kicad_sch` | ERC, `check_schematic.py` | `test_check_schematic.py` |
| 4 | `carry.py` | the step-6 inputs up to the GND fanout; the previous revision's carried record, session and patch table (Rev0.6's), read from Git history at the commit the carry table of `ROUTING_Rev0.7.md` names | `routing/carried.json` | `carry.py --check`; `make_pcb.py`, which refuses a record made for another board or from other sources | `test_carry.py` |
| 5 | `autoroute.py` | what `make_pcb.py --dsn` writes from the step-6 inputs, the carried record included | `routing/usb-power-hub.ses`, `routing/autoroute.json` | `make_pcb.py`, which refuses a session made from other input | — |
| 6 | `make_pcb.py` | the schematic's exported netlist, `PLACEMENT_Rev0.7.md`, `ROUTING_Rev0.7.md`, the carried record, the session, the footprints | `.kicad_pcb` | `make_project.py --check`, `check_pcb.py`, `check_routing.py` (each with DRC), `check_silk.py` | `test_check_pcb.py`, `test_check_routing.py`, `test_check_silk.py` |
| 7 | `make_outputs.py` | the project in `source/`, `design/ecad/jlcpcb_model_frame.json` | `manufacturing/working/rev0.7/`: Gerber and drill zip, JLCPCB BOM and CPL, hand-solder list, schematic and assembly PDFs, two renders, ERC and DRC reports, `RELEASE_MANIFEST.md` (state `WIP`), `SHA256SUMS.txt` | `check_outputs.py` | `test_check_outputs.py` |

```sh
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_project.py
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_libraries.py
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_schematic.py
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/carry.py
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/autoroute.py --java <java.exe> --jar <freerouting-2.5.0.jar> --passes 8
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_pcb.py
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/make_outputs.py
```

Step 4 needs the repository's Git history: it reads Rev0.6's carried record, session and patch table at the
commit the carry table names, and takes about 8 s on this machine. It is needed only when its
inputs change: `make_pcb.py` stops and asks for it when the record no longer matches the carry
table or the board before the carry.

Step 5 needs Freerouting 2.5.0 and a Java runtime, which are not in the repository; the
script refuses any jar or runtime other than the pinned ones (their SHA-256 is in the
script). It is needed only when its input changes: `make_pcb.py` stops and asks for it when
the session no longer matches the board it would route. The committed session took about
5 min on this machine (8 passes, single-threaded; `ROUTING_Rev0.7.md`, *Router*, says why more
passes change nothing while the carried copper is fixed). A new record or a new session also
needs a new patch table (`ROUTING_Rev0.7.md`, *After the router*).

`make_project.py` writes a bare board, so `make_pcb.py` runs after it; until then
`check_pcb.py` fails, because the board holds no footprints. A re-run of any generator but
`make_pcb.py` writes the same bytes: UUIDs are derived, and `make_pcb.py` seeds pcbnew's UUID
generator, which decides the order footprints are saved in.

`make_pcb.py` writes the same bytes except for the pours' fill: KiCad's zone filler is not
deterministic. Measured on the Rev0.5 board (commit `866ef44`): in 32 runs on 2026-11-13 (a
scratch copy of `design/`, `--no-check`), 3 left out two 0.11 mm² islands of the B.Cu GND pour
that touched pad J3.S1 where it then stood (x 96.73-97.23 and 105.37-105.87, y 117.0-117.3 mm)
and 29 kept them; the board file then differed by those two filled polygons and the Gerber's
`B_Cu` member with it. Nothing else differed, and both boards passed every check. The Rev0.6 board
has not been run that way. The tracked `source/usb-power-hub.kicad_pcb` is therefore the source of
truth, and a release is made from it. Do not regenerate it to compare, and read a changed board
hash after a re-run as this, not as a changed design, before looking for another cause. Step 7 is
deterministic given the board.

Step 7 writes a candidate, not a release. `manufacturing/working/` is not tracked
(`.gitignore`; CLAUDE.md §2: disposable, never orderable), so the set is regenerated rather
than checked out: the same sources, the board included, give the same bytes, because creation
dates are fixed to 1980-01-01 and paths made relative. Its manifest records the SHA-256 of every source file
instead of a Git commit, and `check_outputs.py` fails a set older than its sources. A
release is copied to `manufacturing/releases/<rev>/<rNN>/` and tracked there (CLAUDE.md §2).

The CPL's angles are KiCad's plus a per-LCSC rotation, and its positions KiCad's plus a per-LCSC
shift; both are in `jlcpcb_model_frame.json` (until 2026-11-13 `jlcpcb_model_rotation.json`,
rotations only), because JLCPCB applies a CPL point and angle to its own model of the part
(easy-stick 14.18). `make_outputs.py` reads it and `check_outputs.py` fails an entry no BOM line
uses. Gerber and drill files are written with the auxiliary origin at the board's lower-left
corner, the CPL's origin. A new entry or a new part class is confirmed only in JLCPCB's
placement preview, after the corrected CPL is uploaded; the first review is
`manufacturing/releases/rev0.4/r01/JLCPCB_REVIEW.md`, and its candidate release is the first one
under `manufacturing/releases/` (state `WIP`, not approved). Rev0.4's `r02` beside it is the
same copper with every via drilled at 0.30 mm, JLCPCB's standard via class (issue #8); its
`JLCPCB_REVIEW.md` records only what changed. Rev0.5's gate ran on 2026-11-13 on
`manufacturing/releases/rev0.5/r01/` and found two defects: the receptacle C2765186's (D37)
model sat 1.375 mm off the CPL point, hence the `shift`, and eight vias stood 0.046 mm from the
receptacles' plated slots, hence rule 10 of `check_routing.py` and the *Slot vias* stage of
Rev0.5's routing patch (since Rev0.6 the GND fanout draws those stubs itself).
`manufacturing/releases/rev0.5/r02/` fixes both (state `WIP`, not approved); its
`JLCPCB_REVIEW.md` is the gate's record, and r01's beside it a short one.

The negative tests corrupt copies of the files in a temporary directory and expect the
checker to name each fault; they never write to `source/`, `libraries/` or `manufacturing/`.

## Independent check of a candidate set

`check_outputs.py` reads the board with `pcbnew`, as `make_outputs.py` does.
Two more scripts read the files JLCPCB receives against the board's text, by regular
expressions. They import nothing from this directory and no KiCad module (KiCad's Python serves
as a plain interpreter), and they are not a pipeline step: run them on a release candidate, after
`sha256sum -c` (CLAUDE.md §12, the manifest's gate "Independent check of the set").

| Script | Reads | Checks | Corruptions |
|---|---|---|---|
| `independent_check_sets.py` | the Gerber zip, the CPL, the BOM, the hand-solder list, the silkscreen table of `PLACEMENT_Rev0.7.md`, the board | 30 with three fiducials: no Bottom paste, the outline, each fiducial in copper and mask, the CPL's side and bounds, the hand-solder list apart from BOM and CPL, BOM against CPL, the 16 test pads of REQ-MFG-04 | 8 |
| `independent_check_positions.py` | the Gerber zip, the CPL, the BOM, the hand-solder list, the board, `jlcpcb_model_frame.json`, the previous release's Gerber zip and CPL | 13: the parts and their codes in the three lists, every CPL point and rotation, every Top paste flash, every hit of the two drill files | 16, three of them the previous release's files in the place of this set's |

```sh
R=manufacturing/working/rev0.7/UsbPowerHub_Main_Rev0.7
P=manufacturing/releases/rev0.5/r02/UsbPowerHub_Main_Rev0.5
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/independent_check_sets.py \
    ${R}_Gerber.zip ${R}_CPL_JLCPCB.csv ${R}_BOM_JLCPCB.csv ${R}_HandSolder.csv \
    design/ecad/PLACEMENT_Rev0.7.md design/ecad/source/usb-power-hub.kicad_pcb
"<KiCad 9.0>/bin/python.exe" -I -B design/ecad/scripts/independent_check_positions.py \
    ${R}_Gerber.zip ${R}_CPL_JLCPCB.csv ${R}_BOM_JLCPCB.csv ${R}_HandSolder.csv \
    design/ecad/source/usb-power-hub.kicad_pcb design/ecad/jlcpcb_model_frame.json \
    ${P}_Gerber.zip ${P}_CPL_JLCPCB.csv
```

Each prints `PASS` or `FAIL` per check, then `CAUGHT` or `MISSED` per corruption, and exits 0
only when every check passed and every corruption was caught (1 otherwise, 2 for a wrong number of
arguments). The corruptions are made on in-memory copies in the same run, so a result always comes
with the proof that the checker can fail; neither script writes a file, and neither has a `test_`
script. On Rev0.6 r01 (2026-11-19): 30 checks, 0 failed, 8 corruptions, 0 missed, and 13 checks,
0 failed, 16 corruptions, 0 missed, in 0.3 s and 0.6 s on this machine. Rev0.6 r02 and Rev0.7
r01 give the same figures. The second script's last argument must be a set of another PCB revision: r01 beside r02
shares its CPL, paste and drill files, so three of the corruptions made from it change nothing and
are reported `MISSED`.

The first script reads no position but the fiducials': with Rev0.5 r02's CPL beside the Rev0.6
board it passes all 30 checks, and the second then fails on 28 CPL rows. The second is therefore
the one that tells a layout revision's set from the one before, and its last two arguments must
name a release whose parts and holes stand elsewhere: with a release given as its own predecessor
the three substitutions are no corruption, they are reported `MISSED`, and the exit status is 1.

Both take the board as right. They show that the BOM, the CPL, the hand-solder list, the Top
paste Gerber and the two drill files are this board's; they read no copper, mask or silkscreen
layer and no pad shape (each docstring's "What it CANNOT see"). Until 2026-11-19 they were scratch
scripts outside the repository, `c2_check.py` (issues #6 and #8) and `c2_ext_rev06.py` (issue #13),
and records written before that day name them so.

## Where a change starts

| Change | Edit | Then run |
|---|---|---|
| A part, pin or net | the capture list | steps 3 to 7 |
| A part's position or rotation | `PLACEMENT_Rev0.7.md` | steps 4 to 7 |
| A silkscreen label | `PLACEMENT_Rev0.7.md`, *Silkscreen* | steps 6 and 7 (labels are not router input) |
| A hand-drawn track, a zone, a router class or keepout | `ROUTING_Rev0.7.md` | steps 4 to 7 |
| A row of the carry table (*Carried from Rev0.6*) | `ROUTING_Rev0.7.md` | steps 4 to 7 |
| A row of the patch table (*After the router*) | `ROUTING_Rev0.7.md` | steps 6 and 7 (the record and the session stay: the patch is not router input) |
| A part's JLCPCB model rotation or shift | `jlcpcb_model_frame.json` | step 7, then the JLCPCB placement preview |
| A symbol or footprint | `libraries/library.json`, `make_libraries.py` | steps 2 to 7 |
| Rules, net classes, stackup, outline | `make_project.py` | step 1, then 4 to 7 |

## What the checks cannot see

Each checker's docstring ends with a "What it CANNOT see" list (CLAUDE.md §8). In short: the
checkers compare the KiCad files with the documents, not the documents with the physics.
Whether the circuit is right is the circuit document's and its `_calc.py`'s; whether the
routing is good beyond the rules `check_routing.py` lists is a review's (its rule 9 reads the 2-D
copper fill of L2, as voids and exposed-pad webs, and not the return currents: a void shorter
than 3.0 mm still lengthens a return path, and the router, which knows no antipad, sees none of
it); heights, the plug overmold and the enclosure are V-MECH-01's; whether JLCPCB reads the set as
meant (DFM, part mapping, the CPL's origins and angles in its placement preview) is the JLCPCB
gate's (CLAUDE.md §8, easy-stick 14.18).
