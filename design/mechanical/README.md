# Enclosure (Rev0.1, issue #11)

> **WIP — NOT PRINTED, NOT ORDERED.** A first design on paper for the Rev0.5 board: a printed
> tray and frame under a PCB lid. Nothing is printed, no cable has been tried in an opening,
> and the lid PCB is not drawn. `ENCLOSURE_Rev0.1.md` is the design; start there.

Everything under `reference/`, `assembly/` and `reports/` is generated by the scripts in
`scripts/`. Change the document (or the board), then re-run the generator. A file edited by
hand is found by the checker (E01) or overwritten by the next run.

| Path | Holds |
|---|---|
| `ENCLOSURE_Rev0.1.md` | The design: decisions E1–E9, the parameter table, the part heights, the derived figures, what the checker proves and what it cannot see, hardware, printing and assembly, what is not verified. |
| `reference/board_interface_Rev0.5.json` | The board as the enclosure sees it: outline, thickness, every footprint's position and courtyard, every drilled hole. The one dimension source (CLAUDE.md §7). |
| `assembly/` | The three STL files, each in its print orientation, the lid PCB's interface (outline, holes, windows) and the manifest that ties them to the document and the board. |
| `reports/` | Seven pictures of that build. For looking at; they prove nothing. |
| `scripts/` | The generators, the checker and the checker's negative tests. |

## Pipeline

From the repository root, in this order.

| Step | Script | Python | Reads | Writes | Checked by |
|---|---|---|---|---|---|
| 1 | `export_board_interface.py` | KiCad 9.0's | `design/ecad/source/usb-power-hub.kicad_pcb` | `reference/board_interface_Rev0.5.json` | E01 (the interface still describes the tracked board). Its content is not checked: see below. |
| 2 | `make_enclosure.py --derived` | the CAD venv's | the document's parameter and height tables, the board interface | `assembly/`: three STL files, the lid interface, the manifest; the document's derived-figures table; then it runs steps 3 and 4 | `check_enclosure.py` |
| 3 | `render_enclosure.py` | the CAD venv's | `assembly/`, the board interface, the document's tables | `reports/`: seven PNG files, each naming the manifest it was drawn from | E16 |
| 4 | `check_enclosure.py` | the CAD venv's | all of the above, as files | — (96 `PASS`/`FAIL` lines, exit status) | `test_check_enclosure.py` |
| 5 | `test_check_enclosure.py` | the CAD venv's | builds of its own in temporary directories | — | — |

```sh
"<KiCad 9.0>/bin/python.exe" -I -B design/mechanical/scripts/export_board_interface.py
<venv>/Scripts/python.exe -I -B design/mechanical/scripts/make_enclosure.py --derived
<venv>/Scripts/python.exe -I -B design/mechanical/scripts/test_check_enclosure.py
```

Step 1 is needed only when the board changes; the checker says so (E01) when the tracked
board is no longer the one the interface was exported from. Step 2 takes about 20 s, nearly
all of it the pictures (the build itself takes under 1 s); step 5 about 1 min.

The CAD venv holds `manifold3d`, `numpy` and `trimesh` and nothing else that the scripts
import; the manifest records the versions that built the files (Python 3.13.17, numpy 2.5.4,
manifold3d 3.5.4; the checker also uses trimesh 5.2.0). On this machine it is
`~/tmp/cadvenv`. `-I` keeps the script directory off `sys.path`, so the scripts load each
other by path (`importlib`), not by `import`.

## What to know before changing something

- **A value has one home.** A dimension of the enclosure is a row of the document's
  parameter table; a part's height is a row of its height table; anything about the board
  comes from the interface file. No script holds a dimension of its own, except the
  checker's own thresholds, which the document's §7 names.
- **The checker does not trust the generator.** `check_enclosure.py` does not import
  `make_enclosure.py`. It reads the STL files as written, puts each back into the assembly
  frame with the manifest's matrix, and tests them with probes it builds itself.
  `enclosure_spec.py` (the tables and the interface) and `enclosure_solid.py` (boxes,
  cylinders, STL reading and writing) are shared by both.
- **A build is byte-reproducible.** Two runs write the same STL, JSON and PNG bytes, so a
  re-run that changes nothing leaves `git status` clean.
- **`--set k=v` and `--out DIR`** build a variant somewhere else, for an experiment or a
  negative test. The manifest records the override and the checker refuses it as "not the
  document's design" (E01). No pictures are drawn of such a build.
- **A union needs volume in common.** Two solids that only share a face stay two bodies in
  the exported mesh (it is watertight, and it is two parts). Every joined solid in
  `make_enclosure.py` overlaps its neighbour by `JOIN`; E02 counts the bodies.

## What the checks do not cover

- The export in step 1 is not checked against a second source. Its positions were compared
  by hand with `design/ecad/PLACEMENT_Rev0.5.md` on 2026-11-13 for J1–J5, H1–H4, SW1–SW3,
  F1, U5 and D10–D13 (18 footprints: position and rotation agree), and no further.
- Everything in the document's §7, *It cannot see*, and §10, *Not verified*: the print, a
  real cable, a real insert, the assumed part heights, strength, light and heat.
  V-MECH-01 and V-BOOT-01 need the built unit.
